# 固定 N4 相位补偿：TRAIN24 探索性复核

2026-10-28。**这是一个事后设计的离线备选，不是预注册通过、闭环结果或论文完成结论。** 当前优先完成既定因果能量门 v2 的闭环核验；本报告没有启动 Plant，也没有实现或启用在线 lead。未读取 VAL/TEST 或旧 `DL1018_TRAIN_*` cohort，未重建惯量，未扫 lead 参数。

## 信号链与目标

- 真正的 C5 是 DSSM14/M110 位置环 + RBF 姿态环；parent 是相同 C5 位置环 + cosine-GRU 姿态环。这里的 action 回放来自 parent 的 C5 position action，不含额外位置 residual-GRU。先前的 noGRU 双 notch 与 pre-notch residual-GRU 开启的 run 并非单因素对照。
- 设 `a_C5` 为惯性系的最终位置残差加速度估计，100 Hz 更新、其间零阶保持。设 `u` 为经滤波后的加速度估计，运行链接为 `residualForce = m*u`，而 `position_bs_step` 明确使用 **`F_cmd = F_nominal - residualForce`**。随后由 `baseline_force_to_attitude` 生成推力和姿态目标，经 command filter 和姿态内环驱动；日志字段 `stage1_position_injected_force_I_N` 是控制器接口量，不是直接额外施加到 Plant 的真实外力。
- 冻结 scorer 的 `task_SO3` 是实际姿态相对于由参考加速度、重力、偏航和倾角限制构造的任务姿态的测地 RMSE；`inner_SO3` 是相对滤波后姿态指令的误差。减小内环误差不必减小任务姿态误差。高频风组 task 指标是全时域测度，也不是单独某个 2–5 Hz 谱线能量。
- W09 两场 noGRU+双 notch 的 task 与 Q 均胜 B，但两场平均 Q 比 B 好 11.83%，不能证明整组约 32% 的位置优势。固定 N4 已在 W09 T3 通过当场 task/B 和 Q/C5 诊断，但 W03 T1 Q/C5 = 1.06858，超过此前固定的 1.05 场景筛查阈值。与此同步，N4 的 0.05–0.5 Hz 群延迟约 49–54 ms；它是位置恶化的合理风险，**并非已证实的唯一原因**。
- 四个固定中心源自已见 TRAIN24 风谱，离线对齐真实场景频率；部署不使用 W 码或风真值，但结果不能因此等同于对未知频率的泛化。动作与风、target 同频不证明去除它们会改善闭环。

## 备选设计与参数来源

仅作为一个固定备选，保留既定 100 Hz 四段 notch（2.2/3.2/3.7/4.8 Hz，Q=4），然后接一阶因果相位超前：

`C(s) = (1 + 0.08 s) / (1 + 0.03 s)`。

其选择依据是已有 N4 的低频延迟接近 0.05 s：低频下超前网络相位斜率约由 `0.08 - 0.03 = 0.05 s` 决定。`0.03 s` 是研究者手选的单一示例，不是从数据拟合出的最优值；二者均非预注册。本次只检查这一组参数，没有替代组、网格搜索或针对 VAL 的选择。

100 Hz 双线性离散化得到 `b=[2.4285714285714284,-2.142857142857143]`、`a=[1,-0.7142857142857143]`，即 `y[k]=2.4285714*x[k]-2.1428571*x[k-1]+0.7142857*y[k-1]`。这是稳定、因果的一阶网络；低频负群延迟只是该网络在有限频带的波形整形，不是使用未来信息或预测未来。

探索性回放按既有 N4 协议，在首个非零 action 对各段作稳态初始化、首样本原样输出；N4 输出按 ±3 m/s² 裁剪，再接 lead 并按同一限幅裁剪。若将来实现，必须固定滤波、初始化、限幅顺序并独立核对这些细节；不能直接把该分析脚本当作飞控实现。

## 回放口径与结果

物理 `TRAIN_C5_24` 的 24 条 `DL1018_DEV_*` 记录，输入为已经锁定的 parent NPZ 的 1,999 个 100 Hz 事件。31 个 pre-ready NaN 为零，其余 action 必须有限。还原成 20,000 个 1 kHz held action 样本，按原 N4 审计的 Hann 频带口径计算 `0.05–0.5 Hz` 内 `RMS(filtered action − original action)/RMS(original action)`，是**向量变化量**，不是仅比较两者的 RMS 幅值。

| 离线量 | 原固定 N4 | N4 + 固定 lead |
|---|---:|---:|
| 0.05–0.5 Hz 群延迟 | 49.426–54.129 ms | -0.526–8.603 ms |
| 24 场低频 action ΔRMS/原 RMS | 3.731%–9.398% | 0.296%–1.064%；中位 0.584% |
| 原 N4 / lead 裁剪次数 | 0 | 0 / 0 |

原 N4 回放数值与既有锁定报告 24 场最大相差 `9.5e-8` 个百分点，主要来自 NPZ float32 动作与原 raw 精度差。此前 N4 协议曾标记 2% 低频风险；这次 24 个数字均低于 2% 只是**事后观察**，不能追称为 lead 方案预注册通过，也不保证未见轨迹或闭环位置。

完整逐场数据见 [TRAIN24_FIXED_LEAD_ACTIONS_v1.csv](TRAIN24_FIXED_LEAD_ACTIONS_v1.csv)，输入 NPZ SHA-256 `15d689f08fd6d8a53a64c59dbdf62b33f9b8e8a12ce083fb12834cd106df2eeb`。数据由 [audit_fixed_lead_n4.py](audit_fixed_lead_n4.py) 复算，[JSON](EXPLORATORY_FIXED_LEAD_N4_RESULT_v1.json) 保存参数与摘要。parent attitude 在这些场景见过数据；不是独立验证。

## 可证伪的后续设计（不在本次运行）

在 v2 门控结果完成后，若仍需单独评估这个备选，事先冻结 lead/N4、相同初值及裁剪顺序；保留 C5 DSSM 位置环和 parent cosine-GRU 姿态环，不开位置 residual-GRU。先做 no-Plant 事件/1 kHz held parity、首非零与零/恒值/步变输入、限幅和高频带外噪声审计，并报告完整幅相。若固定实现无法复现上面离线结果或出现不可接受的噪声/剪裁，停止。

若再开展成对闭环，先固定低频 W03 T1、已配对 W09 T3、W12 高频和 W06–08 过渡频段场景，配相同初态、参考、形变计划及确定性风相位，并绑定 exact parent、C5 和 B 的身份。按场报告候选相对 C5 的 `Q_m`、相对 B 的 `task_SO3`、`inner_SO3`、各轴/分阶段误差和全部限幅；先前 W03 T1 的 1.05 Q/C5 场景门不应因结果放宽。高频场景 task 若仍劣于 B，或低频位置仍超过既定阈值，即拒绝“相位修复足以解决折衷”的假设。均通过也仅是开发筛查，最终仍需全组统计、损失场景和独立冻结评价；约 32% 位置优势须按同一最终评估 cohort 的实际宏平均重算。

## 其他两种不同机制

1. **闭环干预辨识与位置–姿态联合优化。** 对已经稳定的 parent，在 TRAIN-only 场景用预先固定、幅值受限的成对扰动测量 `ΔQ` 和 `Δtask_SO3`，而不是用单轨迹残差预测 RMSE 作为 Q 标签；只拟合少量共享频带增益，再按风频组留出检查。控制输入与扰动会因反馈相关，单看自相关/相关系数可能有偏；原论文讨论了闭环工具变量方法 [Gilson & Van den Hof, Automatica 2005](https://www.sciencedirect.com/science/article/pii/S0005109804002845)。这是辨识–目标层面的不同机制，代价是需要成对闭环数据；不能把本次冻结回放误称干预。
2. **未知窄带周期的因果估计与受限抵消。** 用过去 action/可部署测量估计 2–5 Hz 的窄带分量，只对有足够能量与频率稳定证据的部分低强度修正，并保留低频与参考动作；它按实际观测频率工作，而不是写死四个谱线或用整体高频能量开关。多正弦自适应干扰抑制的原论文见 [IEEE TCST 2009](https://doi.org/10.1109/TCST.2008.922566)。但该论文的线性系统/稳定性假设不能直接转移到此非线性双环；目标高频机动和风同频、频率估计滞后、频率漂移、弱能量误触发都是反例，必须检验未知中间频率和真实参考激励。

几何层面的根本约束是推力方向与位置、姿态相耦合，[Lee 等的四旋翼几何控制原论文](https://mathweb.ucsd.edu/~mleok/pdf/LeLeMc2010_quadrotor.pdf)及[姿态控制分配原论文](https://ieeexplore.ieee.org/document/7991344/)给出相关背景；不能假定修改姿态指令而不改变位置响应。相位超前及 notch 的一般机制可参见 [MathWorks 官方控制系统文档](https://www.mathworks.com/help/control/ug/edit-compensator-dynamics.html)。以上来源支持机制，不证明本参数稳定或本项目结果成立。
