# 姿态学习补偿只读审查

## 结论

C5 并非“仅保留固定姿态反步、没有学习”：它运行固定名义 BS 姿态环和在线姿态 RBF 残差补偿；C5 的单因素改动在位置坐标头，姿态 RBF 仍启用。DL1018 源码已有可用的冻结姿态模型替换接口（`attitude_fusion_v3_6`, `lambda=1`），而且在其 sibling DL1009 项目中找到一份可核验的冻结 A_KAN29 权重与 normalizer。该包尚未集成进 DL1018/C5 的已选模型目录，故它是有身份的候选 checkpoint，不是 C5 已验证替代件。

本次只读读取一个既有 C5 DEV 场景 `T1_C00_W03`，未读 TEST、未运行 MATLAB/Plant/训练、未改实现代码。对应 raw SHA256：`FA36BF4AA229279D964B40C10CB3579487B5C641D167572383EF49F63196AF5D`。

## 当前 C5 姿态链与机制边界

- `experiments/position_axis_coordinate_c5_20261023/run_dl1018_closed_loop.m:616-626` 中 `rbfAtt400` 是方法路径布尔量；实际更新频率从 `cfg.rbf.runtime.attitude_update_hz` 读取。有效配置在 `matlab/runtime/prepare_effective_config_dl1018.m:29-32` 设为 100 Hz。C5 DEV raw 也记录 1,999 个姿态更新事件、每次 `dt=0.01 s`；RBF 权重范数最大 `4.97e-4`、补偿加速度与补偿力矩均非零。该 raw 同时记录 fusion/head 未启用。其 `attitude_event_beta` 列全为 NaN，尽管控制源码按 `min(k*dt/beta_rise_time,1)` 生成实际 ramp；以后若比较 ramp，应记录或从控制时序重构该量，不能把 NaN 当作真实 beta。因而 C5 基线是“位置 C5 + 在线姿态 RBF”，不是姿态学习关闭。
- 独立复算根的单场姿态指标后，确认状态—命令对齐和 ZYX 旋转约定均正确。控制循环在同一 `k` 用左端状态 `x(k,:)` 形成姿态命令并经滤波得到 `ir`，将 `ir.euler/ir.euler_rate` 记在同一 `k`，然后推进至 `x(k+1,:)`（`run_dl1018_closed_loop.m:2250-2255,2609,2631-2632,2693`）；因此 20,000 个 `state[:,0:20000]` 与 20,000 行 filtered reference/rate 应按同一行配对，没有一拍错位。按源码 ZYX `R`、`T` 复算，同根结果一致：SO(3) 跟踪 RMSE `0.0020561154°`、峰值 `0.0055495584°`；Euler 各轴 RMSE `[0.00160348, 0.00128673, 0.00001057]°`；坐标运输后的 body-rate RMSE `[4.4827e-5, 3.5938e-5, 3.3283e-6] rad/s`。这是单个既有 DEV 场景的描述性基线，误差已很小，说明姿态跟踪的改进余量可能有限，不能预设冻结模型替换会更优。
- `matlab/core/attitude_bs_step.m:11-42` 定义 ZYX Euler 角误差 `e=wrap(eta_d-eta)`、Euler 角速度误差 `de=etaRate_d-T(eta)omega` 和面 `z2=etaRate_d+K1e-T(eta)omega`。虚拟 Euler 加速度先按 `T^{-1}(etaDDot-Tdot*omega)` 转成 body 角加速度，再由 `J0` 和陀螺项形成名义力矩；残差力矩从名义力矩中减去。
- C5 的 RBF 输入仅由 Euler 误差与该 Euler 面组成，见 `run_dl1018_closed_loop.m:2293-2321,3390-3398`。RBF 输出标为角加速度 `datt`，经 `dTau=J0(beta*datt)` 映射为力矩，再传给 BS，见 `run_dl1018_closed_loop.m:2320-2321,2516-2523`。根据旧监督标签定义（下节），合理单位解释是 body `omegaDot` 残差，而非 Euler `etaDDot`。
- 这个坐标解释暴露出一个理论匹配问题，但尚不足以称为实现 bug。若 body 残差估计误差为 `d_tilde`，在理想 `J=J0`、忽略离散/饱和且同一残差模型成立时，Euler 面动力学中的补偿交叉项为 `z2' T(eta) d_tilde`。标准梯度抵消项应使用 `T(eta)' z2`；当前 `matlab/core/rbf_mimo_update.m:15-43` 直接用 `z2`，只在小角度近似 `T≈I` 或另有不同证明时吻合。该 DEV 场的 1,999 个姿态事件上，`||T-I||_2` 最大为 `0.16276`（roll 范围 `[-0.1231,0.0351] rad`，pitch `[-0.0779,0.1198] rad`），说明近似不恒等，但这一个场景不足以否定经验有效性或证明闭环不稳定。v39 头的更新已显式使用 `T' z2`，见 `matlab/models/attitude_kan_head_step_v39.m:37-49`。
- 变形失配在 C5 控制器里没有显式形态补偿：`run_dl1018_closed_loop.m:1032-1041` 每步由真 `rho/rhoDot` 构造 Plant，但形式基线的控制器固定在名义初始臂长；`controller_parameters.m:27-55,72-76` 因而使用名义 `J0` 和零 arm-rate 的 `Jdot`。`vehicle_derivative.m:34-36` 的真实动力学包含 `J(t)`、陀螺项和 `Jdot(t)omega`。分配器用控制器矩阵求电机平方转速、再用 Plant 矩阵算实际 wrench，`allocate_control.m:16-24,42-44`，因此随形态变化的分配误差也进入残差。RBF 可从姿态误差间接适应部分合成误差，但不直接观测 `rho/rhoDot` 或真实惯量，也没有显式 `Jdot` 通道；这属于当前适用域和建模假设，不是本次证实的具体控制实现错误。

## 最小替换方案与公平评估口径

最小候选是从 C5 的原始 `cfg/opts` 派生，仅追加上述 A_KAN29 模型（构造所需结构体）、设 `attitude_fusion_v3_6.lambda=1`，并关闭姿态 RBF 的 enabled/update/output 三个开关；为使用当前 v39 X29 评估路径，可保留其接口字段但显式设 `attitude_head_v39.enabled=false`。代码仍会因该字段存在而运行冻结 v39 输出；`enabled=false` 只关闭头部权重更新。X29 history 要累计 32 个姿态事件才 ready，此前融合力矩明确为零，所以评估须单独报告前 31 个事件及 ready 后表现，不能把热身期隐藏或当作无效记录。这样只替换姿态 RBF 残差块，保持位置模型、`M110`、PCF、BS、命令滤波、控制分配、场景和物理输入不变，不重新调用 `PA_F` 工厂以免连带改位置选项，也不启用 `PA_A` 在线头。候选尚未集成或运行。放行前最小静态准备是冻结模型 MAT 的打包映射、normalizer/feature/evaluator 哈希与 32-event 窗口接口；通过 no-Plant parity fixture 后，才可另行审议 C5 DEV 迁移运行。不得从 TEST48 选模型。

只要获准评估，唯一主对照应是同一 C5 位置候选下的“现有在线姿态 RBF”对“冻结姿态模型替换”，两者使用相同初态、物理输入和 DEV 场景。分别报告：过滤后的 roll/pitch/yaw 命令跟踪和任务 yaw `r.euler(3)` 跟踪；主几何角速度误差用 `e_omega=omega-R_actual' R_ref omega_ref`，其中 `omega_ref=T(eta_ref)^{-1} etaRate_ref`，将参考角速度先旋入实际机体系再相减。可另列 `omega-omega_ref` 的直接 body 分量差，但须标为传统坐标分量诊断，不解释为严格几何误差。再报实际姿态矩阵相对过滤命令姿态的 SO(3) 几何角 `acos(clamp((tr(R_ref'R)-1)/2))`，逐轴 Euler 误差、几何 body-rate 误差的 95 分位/最大值，以及 tilt/motor/wrench/model-output 饱和比例。将“跟踪过滤后姿态命令”和“任务 yaw”分开，避免把位置力到滚转/俯仰的外环命令误读成航向要求。保持原 C5 位置 Q 不退步为约束；候选选择只用预先冻结的 DEV 规则，TEST 只可在模型和规则完全冻结后作一次独立评估。
