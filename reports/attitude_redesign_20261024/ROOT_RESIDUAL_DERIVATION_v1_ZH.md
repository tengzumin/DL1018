# 新姿态设计：残差与因果边界主审核草稿

本记录基于实际读取的 `vehicle_derivative.m`、`allocate_control.m`、`allocation_matrix.m`、`controller_parameters.m`、`attitude_bs_step.m` 和 `export_attitude_events_dl1018.m`。这里只确定物理边界，尚不冻结输入或网络。

令 omega 为机体系角速度，J 为真实惯量，J0 为固定名义惯量，q 为四路实际电机平方转速，A 为真实分配矩阵的三行力矩部分，tau_w 为风力矩。实际角加速度为

`omegaDot = J^-1 [A q + tau_w - omega × (J omega) - Jdot omega]`。

控制器请求 `tau_req = tau_BS - tau_comp`。固定名义系统在相同状态和相同请求下的角加速度为

`omegaDot_0 = J0^-1 [tau_req - omega × (J0 omega)]`。

固定名义模式的 Jdot 为零。若将来改变此条件，必须显式保留相应名义 Jdot 项。

因此与当前日志导出定义一致的物理残差是

`d = omegaDot - omegaDot_0`，单位 rad/s²，输出坐标为机体系。

这个量包含惯量、惯量导数、分配误差、执行器裁剪和风力矩的合成影响，不是只由风决定的外生扰动。

在无裁剪、瞬时电机的简化条件下，令 C 为完整真实分配矩阵、C0 为名义分配矩阵、u_req=[thrust_req;tau_req]，则 q=C0^-1 u_req，得到

`d = J^-1 A C0^-1 u_req - J0^-1 tau_req + J^-1[tau_w - omega×J omega - Jdot omega] + J0^-1[omega×J0 omega]`。

有裁剪时必须回到实际 q 的公式，不能继续将线性映射视为精确。该式说明总推力可能通过 CoG/分配失配耦合到姿态残差，也说明补偿输出改变请求力矩后，残差标签的分布随行为策略改变。

## 对新设计的约束

- 不能把当步预测输出所决定的电机命令或请求力矩，反过来当作同一步预测输入，除非真正实现并证明一个明确的隐式求解器；本研究优先避免这种代数环。
- 允许考虑当前补偿前的名义控制量、上一已执行动作及因果历史，但必须逐项论证必要性，明确动作延迟与模型时序。
- 相同姿态误差和误差面，并不唯一决定真实惯量、分配映射和风力矩。因此不能宣称仅 e/s 是物理残差的充分输入。记忆可能帮助推断隐藏状态，但不能保证唯一可辨识。
- 真惯量、真实臂长、真风和实际动力学导数仅用于离线监督/诊断。若采用变形指令，须明确它是部署可得的命令信息，不能称为完全不含形态相关信息。
- 旧 X29/旧权重不再作为设计起点。共同物理控制基座保留，新特征、模型与更新律需单独审核。

## 数据现状

只读目录计数得到 `data/events/attitude/train` 下 768 个目录、`val` 下 48 个目录。这个计数不等于身份合格的训练/验证集数量；尚未证明文件完整性、拆分独立性、控制器身份或标签可重建性，不能直接投入训练。

下一步由执行设计审查与独立物理复核共同回答：哪些最小部署信息值得保留、是否需要短记忆、如何建立行为条件一致的监督，以及如何冻结公平开发对照。当前没有放行新训练或 Plant。
